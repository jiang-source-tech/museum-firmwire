# 小新底部字幕统一右向左循环流动设计

## 背景

小新当前的底部字幕由 `LcdDisplay::SetChatMessage()` 统一接收。绑定设备时的验证码提示、系统提示、错误信息、用户语音识别结果和助手回复最终都会进入这条路径。

现有实现使用 LVGL 定时器，每 55 ms 截取并显示更长的 UTF-8 字符串前缀。这是逐字追加的打字机效果，不是文字在空间上从右向左移动。标签虽然配置了 `LV_LABEL_LONG_SCROLL_CIRCULAR`，但 LVGL 只有在文字宽度超过标签宽度时才滚动，因此短文本不会移动；逐字刷新还会持续重算标签和滚动状态。

## 目标

小新底部字幕栏中的所有非空文字必须使用同一种像素级右向左流动效果：

- 文字从字幕可视区域右边界之外进入；
- 以固定速度连续向左移动；
- 完全离开左边界后立即从右侧重新开始；
- 无论文字长短，都必须执行动画；
- 新字幕到达时，立即终止旧字幕，并让新字幕从右侧重新开始；
- 空字幕立即停止动画、清空文字并隐藏字幕栏。

## 范围

本次修改覆盖小新简单界面中的底部字幕栏，以及所有进入该字幕栏的消息来源和角色，包括：

- 激活或绑定设备时的验证码提示；
- `system` 系统消息和错误提示；
- `user` 用户语音识别文字；
- `assistant` 助手回复；
- 其他通过 `Display::SetChatMessage()` 进入同一底栏的非空文本。

微信气泡式聊天界面不属于本次修改范围。通知卡片、设置页面、顶部状态栏和其他独立文本组件也不受影响。

## 方案选择

### 采用：自定义像素级位移动画

字幕栏作为固定宽度的裁剪视口，字幕标签按内容实际宽度布局。完整文字一次性写入标签，然后通过 LVGL 动画改变标签的 X 坐标。

采用该方案的原因：

- 不依赖文字是否超过视口宽度；
- 短文本和长文本行为一致；
- 可以精确控制起点、终点、速度、循环和消息切换；
- 运动是像素级连续位移，不会产生字符级跳动；
- 不需要修改或复制文字内容，因此不会破坏 UTF-8 中文文本。

### 不采用：强制触发 `LV_LABEL_LONG_SCROLL_CIRCULAR`

通过补空格或复制文本使短文本强制超宽，会把动画行为绑定到 LVGL 的文字宽度判定和内部循环策略。启动位置、循环间距和新消息立即重启都难以精确保证。

### 不采用：字符窗口滚动

逐步删除左侧字符并添加右侧字符只能提供离散的字符级移动。中文、数字和标点的字宽不同，视觉速度不均匀，也无法达到平滑流动效果。

## 组件设计

### 字幕视口

`bottom_bar_` 继续承担底部字幕栏容器职责，并启用对子对象的裁剪。字幕超出左右边界的部分不得显示。

字幕栏继续使用当前屏幕底部位置、高度、背景和主题颜色，不改变现有整体布局。

### 字幕标签

`chat_message_label_` 保存并显示完整字幕：

- 使用单行文本；
- 宽度由完整文本的实际渲染宽度决定；
- 不使用 `LV_LABEL_LONG_SCROLL_CIRCULAR` 控制本次动画；
- 不再通过字符串前缀实现逐字追加；
- X 坐标完全由字幕流动动画控制。

### 动画状态

`LcdDisplay` 保存当前字幕动画的必要状态。状态至少应能支持：

- 停止并删除旧字幕动画；
- 在设置新文字后重新测量标签宽度；
- 根据视口宽度和标签宽度计算动画距离；
- 从右侧起点启动无限循环动画；
- 在清空字幕或销毁显示对象时安全停止动画。

不再保留现有的字符偏移量、UTF-8 下一字符边界计算和逐字显示定时器，因为新的动画不切割字符串。

## 动画规则

### 起点

标签左边缘位于字幕视口内容区域的右边界。动画开始时，整段文字在可视区域右侧之外。

### 终点

标签右边缘越过字幕视口内容区域的左边界，即整段文字完全离开可视区域。

### 速度与时长

所有字幕使用同一固定像素速度。动画时长按以下关系计算：

```text
移动距离 = 字幕视口有效宽度 + 字幕标签实际宽度
动画时长 = 移动距离 / 固定像素速度
```

这样不同长度的文字具有相同的视觉移动速度，不会因为文字较长而移动更快或更慢。固定像素速度设为 60 px/s。

### 循环

动画使用线性路径和无限重复。每轮文字完全离开左侧后，下一轮立即恢复到右侧起点。循环过程中不增加一秒启动延迟。

### 新字幕切换

收到新的非空字幕时：

1. 删除旧标签对应的 X 方向动画；
2. 一次性写入完整新文字；
3. 更新 LVGL 布局并获取新文字的实际宽度；
4. 将标签移动到字幕视口右边界之外；
5. 创建并启动新的无限循环动画。

旧字幕不等待当前一轮结束，也不与新字幕交叉显示。

### 空字幕

收到空字符串或空指针时：

1. 删除当前字幕动画；
2. 清空标签文字；
3. 重置标签位置；
4. 隐藏底部字幕栏。

## 数据流

激活消息继续沿用现有调用链：

```text
Application::ShowActivationCode()
  -> Application::Alert()
  -> Display::SetChatMessage("system", message)
  -> PaopaoPetDisplay::SetChatMessage()
  -> LcdDisplay::SetChatMessage()
  -> 启动统一右向左字幕动画
```

用户和助手消息也继续调用 `SetChatMessage()`。调用者不需要判断消息角色、长度或来源，所有动画策略由字幕组件内部统一管理。

## 生命周期与异常处理

- 如果字幕标签尚未创建，`SetChatMessage()` 保持现有的防御性返回和日志行为；
- 如果动画创建失败，至少显示完整文字，不能造成崩溃或悬空引用；
- 清空字幕、清理聊天消息和显示对象析构时必须删除动画；
- 动画不得在标签或字幕栏销毁后继续引用对象；
- 新字幕必须先停止旧动画，再更换文字和重新测量，避免沿用旧文字宽度；
- 所有 LVGL 对象和动画操作继续在现有显示锁保护范围内执行。

## 测试设计

自动化回归测试必须证明以下行为：

1. `system`、`user` 和 `assistant` 角色都调用同一字幕动画入口，不存在角色特例；
2. 新字幕一次性设置完整文字，不再通过 `substr(0, end)` 逐字更新；
3. 不再创建字符流定时器，也不再维护 UTF-8 字符偏移量；
4. 动画起点使用字幕视口右边界；
5. 动画终点确保标签完全离开左边界；
6. 动画使用线性路径和无限重复；
7. 动画时长根据视口宽度、文字宽度和固定像素速度计算；
8. 短字幕与长字幕都无条件创建位移动画；
9. 新字幕会删除旧动画并从右侧重新开始；
10. 空字幕会停止动画、清空标签并隐藏字幕栏；
11. 激活验证码消息仍通过 `Alert()` 和 `SetChatMessage("system", message)` 进入统一路径；
12. 现有小新字幕、错误显示、语音状态和激活路径测试继续通过。

在可用硬件上还应进行一次实机视觉检查，确认短文本、中文长文本、验证码提示和连续消息切换均为平滑右向左运动，没有裁剪泄漏、残影或速度突变。

## 验收标准

- “在控制台输入验证码:xxxxxx”从屏幕右侧进入并持续向左循环；
- 单个短词也执行完全相同的右向左循环动画；
- 长句保持与短句一致的像素速度；
- 任意新字幕到达后，旧字幕立即消失，新字幕从最右侧重新进入；
- 清空字幕后动画停止且底栏隐藏；
- 所有字幕来源无需新增调用方特判；
- 自动化测试和固件构建通过。
